# 4단계: 태블릿 UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 친구들이 가로로 든 태블릿(아이패드, 갤럭시탭)에서 터치만으로 편하게 플레이하도록, 게임 화면을 가로 태블릿(CSS 폭 1024~1366px) 기준 배치 하나로 통일하고 터치 크기·호버 제거·화면 버튼·전체화면·터치 판정·그래픽 기본값을 바꾼다.

**Architecture:** 클라이언트(`src/client/`, `index.html`, `resources/manifest.json`, `resources/lang/`)만 바꾼다. 하단 HUD는 `index.html`의 3열 그리드(가운데 600px 열) 하나로 고정하고, 각 HUD 컴포넌트(Lit, light DOM, Tailwind)에서 `sm:`/`lg:` 분기와 `renderMobile`/`renderDesktop`를 없앤다. 키보드 전용 기능은 새 `<map-controls>`와 기존 상단 오른쪽 사이드바의 44px 버튼으로, 호버 전용 정보는 탭 한 번에 열리는 정보 카드와 화면에 바로 쓰인 문구로 옮긴다. 터치 판정(16px)과 건설 모드의 지도 탭은 `InputHandler` 한 곳에서 처리한다. 국정 패널은 3단계(승리 탭)가 들어간 `domestic-system`을 먼저 병합한 뒤 오른쪽 서랍으로 바꾼다.

**Tech Stack:** TypeScript 6, Lit 3 + Tailwind CSS 4, Vitest 4 (jsdom), jq, Playwright(`run-openfront` 스킬)

**Spec:** `docs/superpowers/specs/2026-10-15-domestic-system-design.md` §14a "별도 트랙: 태블릿 UI (4단계)" (국정 패널 부분은 §10.7과 함께 읽는다). 3단계 계획(`docs/superpowers/plans/2026-10-15-domestic-phase3.md`)의 Task 12(국정 패널 승리 탭)·Task 9(`EventsDisplay`/`WinModal`)가 같은 파일을 건드리므로 순서를 그에 맞췄다.

## Decisions (spec이 정하지 않아 이 계획에서 정한 것)

1. **배치 기준:** 하단 HUD는 `grid-cols-[minmax(0,1fr)_600px_minmax(0,1fr)]` 하나다. 가운데 600px 열에 공격 목록, 조작판(`control-panel`), 건설 단축바, 국정 HUD가 들어가고, 오른쪽 열에 채팅·이벤트·알림이 들어간다. 600px는 단축바 12칸(44px × 12 + 간격 4px × 11 = 572px)에 여백을 더한 값이다. 1366px보다 넓은 화면도 같은 배치이고 양옆 열만 넓어진다("비율만 키운다"를 열 폭으로 해석). 1024px보다 좁은 화면도 같은 배치다(세로 화면은 고려하지 않음).
2. **단축바 탭 동작(모든 기기 공통):** 첫 탭 = 정보 카드(설명, 비용, 막힌 이유, 단축키는 마우스 기기에서만). 같은 칸을 다시 탭 = 건설 모드(유령 건물). 건설 모드인 칸을 또 탭 = 건설 모드 해제. 다른 칸을 탭하면 건설 모드가 풀리고 그 칸의 카드가 열린다. 지도를 누르면(`MouseDownEvent`) 카드가 닫힌다. 지을 수 없는 칸은 두 번째 탭에도 카드만 남는다(이유가 카드에 쓰여 있음). PC 마우스도 같은 2단계 동작이다(spec "모든 기기에 하나의 배치").
3. **건설 모드의 지도 탭:** 지금은 터치 탭이 항상 `TouchEvent`(→ 방사형 메뉴)로 가서, 단축바로 고른 유령 건물을 터치로 놓을 수 없다. 건설 모드(`uiState.ghostStructure !== null`)에서의 터치 탭은 `MouseMoveEvent` + `MouseUpEvent`로 보내 마우스 클릭과 같은 경로(`BuildPreviewController`)로 짓는다.
4. **터치 판정 거리:** 탭/드래그, 길게 누르기 취소, 선택 상자 완료, 알림 위 드래그 취소의 기준을 이벤트마다 `pointerType`으로 고른다(터치 16px, 마우스·펜 10px). 기기 단위(`Platform.isTouch`)가 아니라 이벤트 단위라서 트랙패드를 붙인 아이패드도 맞게 동작한다.
5. **화면 버튼 위치:** 일시정지·전체화면은 이미 상단 오른쪽 사이드바에 있다(일시정지는 혼자 할 때·리플레이·비공개 방장). 크기만 44px로 키운다. 카메라 중앙·보기 전환·좌표 격자는 새 `<map-controls>`(오른쪽 가장자리 세로 가운데, 44px 아이콘 버튼 3개)에 둔다. 아이콘 버튼은 다른 사이드바 버튼처럼 글자 없이 `aria-label`만 둔다.
6. **보기 전환 버튼은 켜기/끄기 토글**이다(Space는 누르는 동안만). 버튼과 키가 같은 상태를 보도록 `InputHandler`가 버스의 `AlternateViewEvent`·`ToggleCoordinateGridEvent`를 따라간다. 버튼으로 켠 뒤 Space를 눌렀다 떼면 꺼진다.
7. **전체화면:** 기존 `document.fullscreenEnabled` 기반 버튼을 그대로 쓴다(아이패드OS 16.4 이상 사파리, 안드로이드 크롬·삼성 인터넷 지원). 아이폰처럼 API가 없으면 버튼을 숨기고, 대신 홈 화면에 추가한 앱이 주소창 없이 뜬다. `webkit` 접두어 대체 경로는 넣지 않는다.
8. **매니페스트:** `orientation`을 `portrait` → `landscape`로 바꾼다. `display: standalone`과 `display_override: ["fullscreen", "minimal-ui"]`는 유지한다. iOS용으로 `apple-mobile-web-app-capable` 등 메타 태그 3개를 `index.html`에 더한다. 기존 iOS "홈 화면에 추가" 안내(`IOSAddToHomeScreenBanner`)는 그대로 쓴다.
9. **중간 그래픽 프리셋:** 기존 프리셋은 "스타일"(기본, 야간, Evan, 색맹)뿐이라 "중간 품질"이 없다. 무거운 효과만 끄는 내장 프리셋 `graphics_setting.preset_medium`(작은 나라 빛 0, 낙진 빛 끔, 수송선·핵 궤적 끔)을 더한다. 터치 기기(`Platform.isTouch`)에서 그래픽 설정을 한 번도 바꾸지 않은 첫 실행에만 이 프리셋을 적용한다. 판정은 기존 일회성 이전 함수 `migrateLegacyGraphicsSettings`가 하며, 프리셋 키를 쓰는 순간 끝나므로 다시 적용되지 않는다. 렌더 해상도(DPR) 상한은 바꾸지 않는다.
10. **길게 누르기 안내:** 터치 기기에서 처음으로 내 군함이 생겼을 때 화면 위 알림(`showToast`, 8초)으로 한 번만 보여 주고 `UserSettings`에 기록한다. 같은 문구를 단축바 군함 카드에도 쓴다(터치 기기에서는 Shift 안내 대신).
11. **왼쪽 순위표:** "넓은 화면에서만 처음부터 펼침" 규칙(`Platform.isDesktopWidth`)을 없애고 모든 폭에서 스폰 뒤 펼친다(목표 폭 1024~1366에서는 지금과 같은 동작).
12. **바꾸지 않는 것:** 지도 조작(포인터 이벤트, 핀치 줌, 드래그), 방사형 메뉴(d3, 호버 툴팁 포함), 상단 가운데 `PlayerInfoOverlay`(지도 탭으로 이미 열리고, 행동 버튼은 방사형 메뉴에 있음), 홈 화면·내비게이션 컴포넌트(포크 정비 브랜치가 고침), 채팅의 기존 하드코딩 영어("Hide"/"Chat") 문구, 왼쪽 사이드바 게임 ID의 `title=`(조작과 무관한 보조 정보).
13. **국정 서랍:** 화면 전체를 덮는 어두운 배경 없이 오른쪽 40%(`w-[40vw] min-w-[420px]`)만 차지한다. 지도는 보이고 조작도 된다. 닫기는 ✕ 버튼과 국정 HUD의 "국정" 버튼이다. 탭은 `TABS`에 있는 것을 모두 그린다(병합 뒤에는 기술·법률서·정부·승리). 기술 탭은 좁은 서랍에 맞게 "시대별 한 줄 카드" 목록으로 바꾸고 카드에 갈래 이름을 쓴다.
14. **새 번역 키는 쓰는 Task가 함께 추가한다.** 그래서 `tests/TranslationSystem.test.ts`가 모든 Task 끝에 통과한다. 기존 키(`user_setting.center_camera` 등)를 다시 쓸 수 있으면 다시 쓴다.

- jsdom의 `PointerEvent`는 `pointerId`/`pointerType`을 버린다. 일반 `Event`에 `Object.assign`으로 필드를 붙인다(`tests/client/InputHandlerGestureZoom.test.ts` 방식).
- `UserSettings`의 캐시는 static이라 `localStorage.clear()`로 안 지워진다. `(UserSettings as unknown as { cache: Map<string, string | null> }).cache.clear()`도 함께 한다.
- 번역 키 병합(1·2단계와 같은 방법): en.json은 `jq -S`로 정렬하며 병합, ko.json은 순서를 건드리지 않고 병합, 그 뒤 prettier.
- 커밋 전에 바꾼 파일에 `npx prettier --write <files>`.
- Task 12는 `domestic-system`(3단계 승리 탭 포함)을 이 브랜치에 병합하는 단계로 시작한다. 그 전에 3단계가 `domestic-system`에 들어가 있어야 한다(`git log domestic-system --oneline | grep -i "victory tab"`).

## Global Constraints

- 화면에 보이는 모든 문구는 `translateText()`를 거친다. 새 키는 `resources/lang/en.json`(모든 단계 키 알파벳 정렬, `tests/EnJsonSorted.test.ts`)과 `resources/lang/ko.json` **둘 다**에 넣는다. 다른 번역 파일은 건드리지 않는다.
- 홈 화면 청크 규칙(`CLAUDE.md`): `src/client/Main.ts`와 그 정적 import는 게임 클라이언트(`hud/`, `render/`, `view/`, `controllers/`, `ClientGameRunner` 등)를 정적으로 import하지 않는다. 이 계획의 새 HUD 코드(`MapControls`, `TouchHintController`)는 `hud/GameRenderer.ts`에서만 import한다. `LazyModals.ts`의 모달을 직접 부르는 코드를 새로 만들지 않는다. `tests/LayerBoundaries.test.ts`가 통과해야 한다.
- 클라이언트 전용: `packages/engine`, `packages/engine-api`, `packages/engine-lib`, `packages/shared`, `packages/zbin`을 바꾸지 않는다. 엔진 변경이 필요해 보이면 이 계획의 범위 밖이다.
- 테스트: 새 테스트는 `tests/client/`(jsdom)에 두고, 컴포넌트를 실제로 그리고 누르거나 이벤트를 보내 동작을 확인한다. 클래스 문자열 검사는 크기(44px)·배치처럼 jsdom이 잴 수 없는 것을 보조로 확인할 때만 쓴다. 이미 있는 테스트 파일(`tests/GraphicsPresets.test.ts`, `tests/TranslationSystem.test.ts`, `tests/client/ControlPanelAttackRatio.test.ts`, `tests/client/UnitDisplayLock.test.ts`, `tests/client/graphics/GameRendererCreate.test.ts`)은 각 Task가 적은 만큼만 고친다.
- 하나의 배치: 이 계획이 건드리는 게임 HUD 파일에는 `sm:`·`md:`·`lg:`·`xl:`·`min-[…]:`·`max-[…]:` 분기를 남기지 않는다. 기준은 가로 CSS 폭 1024~1366px. 세로 배치와 회전 안내는 만들지 않는다.
- 누르는 요소는 최소 44px(Tailwind `size-11`, `h-11`, `min-h-11`, `min-w-11`), 기본 글자는 14~16px(`text-sm`, `text-base`). 아이콘 아래 작은 배지(개수, 잠금 기술 이름)만 더 작게 쓸 수 있다.
- 호버 전용 정보 금지: 이 계획이 건드리는 파일에 `title=` 툴팁과 `mouseenter`로만 보이는 내용을 남기지 않는다(정보는 화면에 쓰거나 탭으로 연다).
- 지도 조작(포인터 이벤트, 핀치 줌, 드래그)은 판정 거리 외에 바꾸지 않는다.
- 포크 정비(`fork-hygiene` 브랜치)와 충돌을 피한다: 그 브랜치는 `html.self-hosted`와 `.no-self-host`로 계정·상점 UI를 숨기고 `index.html` 머리(`<title>`, 광고·분석 스크립트), `resources/manifest.json`의 `name`/`short_name`, `src/client/styles.css` 맨 위를 바꾼다. 내비게이션·홈 화면 컴포넌트(`desktop-nav-bar`, `mobile-nav-bar`, `play-page`, `page-footer` 등)는 고치지 않고, `index.html` 머리에는 파비콘 줄 **뒤**에만 줄을 더하며, `styles.css`에는 **맨 끝**에만 더한다. 나중에 그 브랜치를 병합할 때 이 세 파일은 서로 다른 줄이라 자동 병합된다.
- `src/client/hud/domestic/*`는 Task 11·12에서만 바꾼다. Task 12는 `domestic-system` 병합으로 시작한다.

## Review Focus

1. **1024px 폭의 겹침과 1024px보다 좁은 화면:** 가운데 600px 열 옆의 이벤트·알림 열이 고정 폭(`w-96`)이면 조작판 위로 넘쳐 겹치고, 1000px 갤럭시탭에서는 가로 스크롤이 생긴다. 양옆 열은 `minmax(0,1fr)`이고 이벤트·알림·채팅은 열 폭을 채워야 한다. 테스트: Task 5 "the in-game bottom HUD is one grid that never forces a horizontal scroll", Task 6 "events fill their column instead of a fixed 384px", Task 13 Step 2의 실제 화면 겹침 검사.
2. **전체화면 API가 없는 브라우저(아이폰 사파리, 오래된 아이패드OS):** 누를 수 없는 전체화면 버튼이 보이면 안 되고, 홈 화면 앱(standalone, 가로)으로 대신한다. 테스트: Task 3 "offers no fullscreen button where the browser has none", Task 2 "launches standalone in landscape".
3. **공격 비율 끝값:** 1%에서 −, 100%에서 +, 1%에서 +(10%로 맞춤), 빠른 선택 뒤 키보드 단축키가 모두 `uiState.attackRatio`와 화면 표시를 같게 유지해야 한다. 테스트: Task 5 "the steppers clamp at 1% and 100% and snap 1% up to 10%", "a preset sets the exact ratio and marks itself pressed".
4. **그래픽을 이미 바꾼 터치 사용자:** 첫 실행 기본값이 기존 사용자 설정을 덮어쓰면 안 되고, 한 번 적용한 뒤 사용자가 바꾼 값도 다음 게임에서 되돌리면 안 된다. 테스트: Task 10 "keeps a touch player's existing custom graphics", "applies only once".
5. **건설 모드에서 지도 탭과 해제 뒤 탭:** 건설 모드의 탭은 짓기여야 하고(방사형 메뉴가 열리면 안 됨), 건설 모드가 풀린 뒤의 탭은 다시 방사형 메뉴 경로(`TouchEvent`)여야 한다. 다른 칸 정보를 열면 건설 모드가 풀려야 한다. 테스트: Task 1 "in build mode a tap places the ghost where the finger landed", "after build mode ends a tap goes back to the menu path", Task 7 "opening another card leaves build mode".

```ts
type PointerType = "touch" | "mouse";

/** jsdom's PointerEvent drops pointerId/pointerType, so fake one. */
function pointer(
  target: EventTarget,
  type: "pointerdown" | "pointermove" | "pointerup",
  x: number,
  y: number,
  pointerType: PointerType,
): void {
  const event = new Event(type, { bubbles: true, cancelable: true });
  Object.assign(event, {
    pointerId: 1,
    pointerType,
    button: 0,
    clientX: x,
    clientY: y,
    x,
    y,
  });
  target.dispatchEvent(event);
}

/** Press at (100, 100), move right by dx, release there. */
function pressMoveRelease(
  target: EventTarget,
  dx: number,
  pointerType: PointerType,
): void {
  pointer(target, "pointerdown", 100, 100, pointerType);
  pointer(target, "pointermove", 100 + dx, 100, pointerType);
  pointer(target, "pointerup", 100 + dx, 100, pointerType);
}

  let eventBus: EventBus;
  let uiState: UIState;
  let handler: InputHandler;
  let seen: object[];

  function of<T>(type: new (...args: never[]) => T): T[] {
    return seen.filter((e): e is T => e instanceof type);

    eventBus.on(ContextMenuEvent, (e) => seen.push(e));
    eventBus.on(TouchLongPressStartEvent, (e) => seen.push(e));
    eventBus.on(AlternateViewEvent, (e) => seen.push(e));
    eventBus.on(ToggleCoordinateGridEvent, (e) => seen.push(e));
    uiState = {
      attackRatio: 0.2,
      ghostStructure: null,

    pressMoveRelease(canvas, 12, "touch");
    expect(of(TouchEvent)).toHaveLength(1);

    pressMoveRelease(canvas, 16, "touch");
    expect(of(TouchEvent)).toHaveLength(0);
  });

  it("a mouse keeps the 10px threshold", () => {
    pressMoveRelease(canvas, 12, "mouse");
    expect(of(MouseUpEvent)).toHaveLength(0);
    expect(of(ContextMenuEvent)).toHaveLength(0);
```

```ts
import { assetUrl } from "@openfront/shared/AssetUrls";
import type { EventBus } from "@openfront/shared/EventBus";
import { html, LitElement, nothing, TemplateResult } from "lit";
import { customElement, state } from "lit/decorators.js";
import type { Controller } from "../../Controller";
import {
  AlternateViewEvent,
  CenterCameraEvent,
  ToggleCoordinateGridEvent,
} from "../../InputHandler";
import { translateText } from "../../Utils";

const centerIcon = assetUrl("images/TargetIconWhite.svg");
const viewIcon = assetUrl("images/TreeIconWhite.svg");
const gridIcon = assetUrl("images/GridIconWhite.svg");

/**
 * On-screen buttons for the map actions that otherwise only have keys
 * (spec §14a): center on my nation (C), the relation view (Space, a toggle
 * here) and the coordinate grid (M). Pause and fullscreen live in the
 * top-right sidebar.
 */
@customElement("map-controls")
export class MapControls extends LitElement implements Controller {
  public eventBus: EventBus;

  @state() private active = false;
  @state() private altView = false;
  @state() private grid = false;

  createRenderRoot() {
    return this;
  }

  init() {
    // The keys and the settings menu flip these too; show what is on.
    this.eventBus.on(AlternateViewEvent, (e) => {
      this.altView = e.alternateView;
    });
    this.eventBus.on(ToggleCoordinateGridEvent, (e) => {
      this.grid = e.enabled;
    });
    this.active = true;
  }

  render() {
    if (!this.active) return null;
    return html`
      <div
        class="fixed right-2 top-1/2 -translate-y-1/2 z-[900] flex flex-col gap-2"
        @contextmenu=${(e: Event) => e.preventDefault()}
      >
        ${this.button(
          "center",
          centerIcon,
          translateText("user_setting.center_camera"),
          null,
          () => this.eventBus.emit(new CenterCameraEvent()),
        )}
        ${this.button(
          "view",
          viewIcon,
          translateText("user_setting.toggle_view"),
          this.altView,
          () => this.eventBus.emit(new AlternateViewEvent(!this.altView)),
        )}
        ${this.button(
          "grid",
          gridIcon,
          translateText("user_setting.coordinate_grid_label"),
          this.grid,
          () => this.eventBus.emit(new ToggleCoordinateGridEvent(!this.grid)),
        )}
      </div>
    `;
  }

  private button(
    id: string,
    icon: string,
    label: string,
    pressed: boolean | null,
    onClick: () => void,
  ): TemplateResult {
    return html`<button
      type="button"
      data-map-control=${id}
      class="size-11 flex items-center justify-center rounded-lg shadow-lg backdrop-blur-sm text-white ${pressed
        ? "bg-sky-700"
        : "bg-gray-800/92 hover:bg-gray-700"}"
      aria-label=${label}
      aria-pressed=${pressed === null ? nothing : String(pressed)}
      @click=${onClick}
    >
      <img src=${icon} alt="" width="28" height="28" />
    </button>`;
  }
}
```

```ts
/**
 * The build bar (spec §14a). Tap once for the unit's card (description,
 * cost, why it can't be built), tap again to build, tap a third time to
 * stop. Nothing is shown on hover, so it works the same with a finger.
 */
@customElement("unit-display")
export class UnitDisplay extends LitElement implements Controller {
  public game: GameView;
  public eventBus: EventBus;
  public uiState: UIState;
  private playerBuildables: BuildableUnit[] | null = null;
  private hotkeys: Record<string, string> = {};
  private counts = new Map<PlayerBuildableUnitType, number>();
  /** The unit whose card is open (after the first tap), or null. */
  private infoUnit: PlayerBuildableUnitType | null = null;
  private tutorialHighlight: PlayerBuildableUnitType | null = null;

  createRenderRoot() {
    return this;
  }

  init() {
    this.hotkeys = new UserSettings().keybinds(Platform.isMac);
    this.eventBus.on(TutorialHighlightEvent, (e) => {
      this.tutorialHighlight = (e.target && TUTORIAL_UNITS[e.target]) ?? null;
      this.requestUpdate();
    });
    // Pressing the map closes the card, like tapping outside a popover.
    this.eventBus.on(MouseDownEvent, () => {
      if (this.infoUnit === null) return;
      this.closeInfo();
      this.requestUpdate();
    });
    this.requestUpdate();
  }

  tick() {
    const player = this.game?.myPlayer();
    if (!player) return;
    player.buildables(undefined, BuildMenus.types).then((buildables) => {
      this.playerBuildables = buildables;
    });
    for (const item of HOTBAR) {
      if (item.countable) {
        this.counts.set(item.type, player.totalUnitLevels(item.type));
      }
    }
    this.requestUpdate();
  }

  private cost(type: UnitType): Gold {
    for (const bu of this.playerBuildables ?? []) {
      if (bu.type === type) {
        return bu.cost;
      }
    }
    return 0n;
  }

  /** Domestic mode: the unit still needs a tech (never true otherwise). */
  private locked(type: UnitType): boolean {
    return (
      this.playerBuildables?.find((bu) => bu.type === type)?.locked === true
    );
  }

  /** Why the unit can't be built right now, or null when it can. */
  private cannotBuildReason(type: PlayerBuildableUnitType): string | null {
    if (this.locked(type)) return lockedReason(type);
    const player = this.game?.myPlayer();
    if (this.cost(type) > (player?.gold() ?? 0n)) {
      return translateText("build_menu.not_enough_money");
    }
    if (
      NUKES.has(type) &&
      (player?.units(UnitType.MissileSilo).length ?? 0) === 0
    ) {
      return translateText("touch_ui.needs_silo");
    }
    if (
      type === UnitType.Warship &&
      (player?.units(UnitType.Port).length ?? 0) === 0
    ) {
      return translateText("touch_ui.needs_port");
    }
    return null;
  }

  private canBuild(type: PlayerBuildableUnitType): boolean {
    if (this.game?.config().isUnitDisabled(type)) return false;
    return this.cannotBuildReason(type) === null;
  }

  /** "1", "⇧B", … for mouse players; a touch screen has no keys to show. */
  private hotkeyLabel(item: HotbarItem): string {
    if (item.keybind === "" || Platform.isTouch) return "";
    return (this.hotkeys[item.keybind] ?? "")
      .replace("Shift+", "⇧")
      .replace("Digit", "")
      .replace("Numpad", "")
      .replace("Key", "");
  }

  private openInfo(type: PlayerBuildableUnitType) {
    this.infoUnit = type;
    this.eventBus?.emit(new ToggleStructureEvent(highlightTypes(type)));
  }

  private closeInfo() {
    if (this.infoUnit === null) return;
    this.infoUnit = null;
    this.eventBus?.emit(new ToggleStructureEvent(null));
  }

  private onItemTap(item: HotbarItem) {
    if (this.uiState.ghostStructure === item.type) {
      // Tapped while building it: leave build mode.
      this.uiState.ghostStructure = null;
    } else if (this.infoUnit === item.type) {
      // Second tap builds. A unit that can't be built keeps its card, which
      // says why.
      if (this.canBuild(item.type)) {
        this.uiState.ghostStructure = item.type;
        this.closeInfo();
      }
    } else {
      // First tap: the card. Looking at another unit leaves build mode.
      this.uiState.ghostStructure = null;
      this.openInfo(item.type);
    }
    this.requestUpdate();
  }

  render() {
    const myPlayer = this.game?.myPlayer();
    if (
      !this.game ||
      !myPlayer ||
      this.game.inSpawnPhase() ||
      !myPlayer.isAlive()
    ) {
      return null;
    }
    const items = HOTBAR.filter(
      (item) => !this.game.config().isUnitDisabled(item.type),
    );
    if (items.length === 0) return null;

    return html`
      <div class="relative border-t border-white/10 p-1 w-full">
        ${this.renderInfoCard()}
        <div class="flex justify-center gap-1">
          ${items.map((item) => this.renderItem(item))}
        </div>
      </div>
    `;
  }

  private renderItem(item: HotbarItem) {
    const selected = this.uiState.ghostStructure === item.type;
    const open = this.infoUnit === item.type;
    const tech = this.locked(item.type) ? requiredTech(item.type) : null;
    const count = this.counts.get(item.type);
    return html`
      <button
```

```ts
import { UnitType } from "@openfront/engine-api/game/GameTypes";
import type { Controller } from "../Controller";
import { Platform } from "../Platform";
import type { UserSettings } from "../UserSettings";
import { showToast, translateText } from "../Utils";
import type { GameView } from "../view";

/** How long the one-time long-press hint stays on screen. */
export const LONG_PRESS_HINT_MS = 8000;

/**
 * A touch screen has no Shift key: warships are box-selected by long-pressing
 * the map and dragging (InputHandler). Says so once (spec §14a), the first
 * time a touch player has a warship, then never again on this device.
 */
export class TouchHintController implements Controller {
  constructor(
    private readonly game: GameView,
    private readonly userSettings: UserSettings,
    private readonly isTouch: () => boolean = () => Platform.isTouch,
  ) {}

  getTickIntervalMs() {
    return 1000;
  }

  tick() {
    if (!this.isTouch() || this.userSettings.touchLongPressHintShown()) return;
    const me = this.game.myPlayer();
    if (me === null || !me.isAlive()) return;
    if (me.units(UnitType.Warship).length === 0) return;
    this.userSettings.setTouchLongPressHintShown();
    showToast(
      translateText("touch_ui.warship_long_press"),
      "green",
      LONG_PRESS_HINT_MS,
    );
  }
}
```

```ts
  // profile that never changed its graphics; writing the presets key makes
  // it a one-time default the player can change in settings.
  if (isTouch && Object.keys(userSettings.graphicsOverrides()).length === 0) {
    const medium = BUILTIN_PRESETS.find(
      (preset) => preset.nameKey === TOUCH_DEFAULT_PRESET_KEY,
    );
    if (medium !== undefined) {
      userSettings.setGraphicsOverrides(medium.overrides);
      userSettings.setGraphicsPresets({});
      return;
    }
  }
```

```ts
function renderLaw(
  ctx: LawsTabContext,
  law: LawId,
  cost: number,
): TemplateResult {
  const d = ctx.view.data;
  const chosen = ctx.view.laws().get(law);
  const block = lawBlock(
    law,
    chosen,
    ctx.view.researchedTechs(),
    d.lawCooldownUntilTick,
    ctx.nowTick,
  );

  return html`
    <div class="border border-gray-600 rounded-md p-3" data-law=${law}>
      <div class="text-base font-bold">
        ${translateText(`domestic.law.${law}.name`)}

          ? html`<span class="text-sm font-normal text-red-300">
              ·
              ${translateText("domestic.locked_requires", {
                tech: translateText(`domestic.tech.${requires}.name`),
              })}</span
            >`
          : null}
      </div>
      <div class="grid grid-cols-2 gap-2 mt-2">
        ${LAW_OPTIONS.map((option) =>
          renderOption(ctx, law, option, chosen, block, cost),
        )}
      </div>
    </div>
  `;

function renderOption(
  ctx: LawsTabContext,
  law: LawId,
  option: LawOption,
  chosen: LawOption | undefined,
  block: LawBlock | null,
  cost: number,
): TemplateResult {
  const key = `domestic.law.${law}.${option}`;
  let status: TemplateResult | string;
  let border = "border-gray-600";
  if (chosen === option) {
    status = translateText("domestic.proclaimed");
    border = "border-green-500";
  } else if (chosen !== undefined) {
    status = translateText("domestic.rejected");
    border = "border-gray-700 opacity-40";
  } else {
    status = proclaimButton(ctx, law, option, block, cost);

  return html`
    <div
      class="border ${border} rounded-md p-3 text-sm flex flex-col gap-2"
      data-option=${option}

      <div class="text-gray-300">${translateText(`${key}.desc`)}</div>

    </div>

  law: LawId,
  option: LawOption,
  block: LawBlock | null,
  cost: number,

      @click=${() => ctx.proclaim(law, option, false)}

      ${translateText("domestic.proclaim")}

    (cost - available) * MILLI,
    ctx.view.pct("goldPaymentCost"),
  );
  const affordable = ctx.gold >= gold;
  return html`<button
      type="button"
      class="${BUTTON} bg-amber-700 hover:bg-amber-600"
      ?disabled=${block !== null || !affordable}
      @click=${() => ctx.proclaim(law, option, true)}

        gold: renderNumber(gold),

      ? html`<span data-reason class="block mt-1 text-red-300"
          >${translateText("build_menu.not_enough_money")}</span
        >`
      : null}`;
}
```

```ts
function renderTierProgress(d: DomesticData): TemplateResult {

      ${translateText("domestic.gov_max_tier")}

          next,
          tier: d.governmentTier + 1,

          class="h-3 bg-violet-500 rounded-sm"
          style="width: ${Math.round(done * 100)}%"
        ></div>
      </div>
    </div>
  `;
}

function renderGovernment(
  ctx: GovernmentTabContext,
  government: GovernmentId,
): TemplateResult {
  const d = ctx.view.data;
  const def = GOVERNMENTS[government];
  let status: TemplateResult | string;
  let border = "border-gray-600";
  if (d.government === government) {
    status = translateText("domestic.gov_active");
    border = "border-green-500";

      d.governmentTier,

      class="border ${border} rounded-md p-3 text-sm flex flex-col gap-1"

      </div>
      <div class="text-gray-400">${status}</div>

function blockText(block: GovernmentBlock, def: GovernmentDef): string {

    case "tierNotReached":

    case "tierPassed":

    case "chosen":

      return translateText("domestic.gov_requires_law", {
        law:
          req === null
            ? ""
            : translateText(`domestic.law.${req.law}.${req.option}.name`),
```

```js
    const overlap = (a, b) =>
      !!a &&
      !!b &&
      a.width > 0 &&
      b.width > 0 &&
      a.left < b.right &&
      b.left < a.right &&
      a.top < b.bottom &&
      b.top < a.bottom;
    const panel = rect("control-panel");
    const bar = rect("unit-display");
    const events = rect("events-display");
    const controls = rect("map-controls > div");
    const small = [
      ...document.querySelectorAll(
        "[data-bottom-hud] button, game-right-sidebar aside button, map-controls button",
      ),
    ]
      .filter((b) => {
        const r = b.getBoundingClientRect();
        return r.width > 0 && (r.width < 44 || r.height < 44);
      })
      .map((b) => b.outerHTML.slice(0, 100));
    return {
      horizontalScroll:
        document.documentElement.scrollWidth > window.innerWidth,
      eventsOverPanel: overlap(events, panel),
      eventsOverBar: overlap(events, bar),
      barVisible: !!bar && bar.height > 0,
      hotbarButtons: document.querySelectorAll("[data-hotbar]").length,
      mapControlsVisible: !!controls && controls.height > 0,
      small,
    };
  });
  await page.screenshot({ path: `${OUT}/tablet-${name}.png` });

  await page.click('[data-domestic="open-panel"]');
  await page.waitForTimeout(500);
  const drawer = await page.evaluate(() => {
    const r = document
      .querySelector("[data-domestic-drawer]")
      ?.getBoundingClientRect();
    return r ? { left: r.left, width: r.width } : null;
  });
  await page.screenshot({ path: `${OUT}/tablet-${name}-drawer.png` });

  console.log(JSON.stringify({ viewport: name, hud, drawer }));
  if (
    hud.horizontalScroll ||
    hud.eventsOverPanel ||
    hud.eventsOverBar ||
    !hud.barVisible ||
    hud.hotbarButtons !== 12 ||
    !hud.mapControlsVisible ||
    hud.small.length > 0 ||
    drawer === null ||
    drawer.width > viewport.width * 0.5
  ) {
    failures++;
  }
  await browser.close();
}
process.exit(failures === 0 ? 0 : 1);
```

- [ ] **Step 3: 실제 태블릿 수동 점검(주인에게 넘길 목록)**

자동 확인은 터치를 흉내 내지 않는다. 아이패드와 갤럭시탭(가로)에서 주인이 다음을 확인한다:
1. 사파리 "홈 화면에 추가"(갤럭시탭은 크롬 "앱 설치")로 띄우면 주소창 없이 가로로 열린다.
2. 게임 안 오른쪽 위 전체화면 버튼(지원하는 브라우저에서만 보임)이 전체화면을 켜고 끈다. 혼자 하기에서 일시정지 버튼이 동작한다.
3. 손가락으로 지도를 살짝 흔들며 탭해도 탭으로 인식되고(방사형 메뉴가 열림), 길게 끌면 지도가 움직인다. 두 손가락 확대·축소가 그대로 된다.
4. 단축바: 한 번 탭하면 정보 카드(설명, 비용, 막힌 이유), 다시 탭하면 건설 모드, 지도를 탭하면 그 자리에 지어진다. 잠긴 유닛 아이콘 아래에 필요한 기술 이름이 보인다. 연구소·행정청 칸이 있다.
5. 공격 비율: −/+와 25/50/75/100% 버튼, 굵은 슬라이더가 손가락으로 쉽게 맞는다.
6. 오른쪽 지도 버튼: 카메라 중앙, 보기 전환(켜고 끄기), 좌표 격자가 동작한다.
7. 처음 군함을 가졌을 때 "지도를 길게 누른 뒤 끌면…" 안내가 한 번 뜨고, 다음 게임에서는 뜨지 않는다. 길게 누른 뒤 끌어서 군함 여러 척을 고를 수 있다.
8. 처음 실행한 태블릿의 설정 → 그래픽 프리셋이 "중간 (태블릿)"이고, 다른 프리셋으로 바꾸면 다음 게임에도 유지된다.
9. 국정 버튼을 누르면 오른쪽 서랍이 열리고 지도가 계속 보인다. 탭·카드·버튼이 손가락 크기이고, 설명과 막힌 이유가 화면에 쓰여 있다. 승리 탭이 있다.
10. 튜토리얼(혼자 하기 첫 판)의 건설 단계가 단축바 두 번 탭으로 진행된다.
