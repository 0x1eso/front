## 1. 의도와 범위

### 1.1 목표

- 1936~1939년 군비 경쟁이 판의 앞 17분을 채운다: "민간 공장을 언제까지 짓고 언제 군수로 넘어가나", "어느 장비에 공장을 몇 개 넣나", "석유·텅스텐을 어디서 사 오나", "어떤 기술을 먼저 하나"가 HOI4처럼 고민거리가 된다.
- 원작 병력과 타일 공격은 그대로 두되, **병력이 인력과 장비에 묶인다.** 전쟁에서 잃은 병력은 공장이 만든 장비와 남은 인력으로만 메울 수 있다.
- 폰·태블릿에서 한 손가락으로 다룰 수 있는 화면(서랍 하나, 탭 4개, −/+ 버튼).

### 1.2 비목표 (뒤 단계)

| 빼는 것 | 단계 |
|---|---|
| 사단·편제·훈련, 장비가 사단에 들어가는 것 | P2 (P1의 전투 다리를 대체) |
| 요새, 해군·공군 기지, 레이더, 대공포 건물 | P2(요새), P4(그 밖) |
| 조선소 건설과 함선 생산, 합성 정유소, 연료 | P4 |
| 정치력, 법 비용, 고문(산업 고문 포함), 국민정신, 중점(연구 칸 +2) | P3 |
| 해상 무역 손실, 수송선단 | P4 |
| 랜드리스, 노획 | P5 |
| 설계기, 군산복합체, 면허 생산, 석탄·에너지 | P6 |

### 1.3 실패 조건

- 옵션이 꺼진 게임이 지금과 조금이라도 다르다.
- 하루 처리 한 번이 폰에서 한 틱 예산을 넘는다(목표: 79개국 하루 전체가 데스크톱 2ms 이하, 한 틱에 나눠진 몫은 0.5ms 이하).
- 독일이 1939년 9월까지 군수 공장을 늘리지 못하거나, 반대로 1937년에 소련보다 군대가 커진다(밸런스 스크립트로 확인, §16).
- 장비가 없어도 병력이 원작처럼 1분 안에 다 찬다.
- 엔진과 화면이 같은 주 건물 숫자를 다르게 본다.

## 2. 시간과 하루 처리

- 날짜는 P0 그대로: `dayIndex(t) = t ≤ 600 ? 0 : floor((t − 600) × 2 / 15)`. 하루 = 7틱 또는 8틱.
- **나라 나누기:** 날 `d`의 첫 틱을 `s = dayStartTick(d)`라 하면, 틱 `t`의 순번 `k = t − s`(0~7)에서 `smallID % 7 === k`인 나라들을 처리한다(`k = 7`인 틱에는 나라가 없다). 하루가 최소 7틱이라 모든 나라가 날마다 정확히 한 번 처리된다.
- **하루 공통 처리**(`k = 0`, 나라보다 먼저): 주 통제 갱신(§4.6), 무역 검사(§7.5).
- **나라 처리 순서**(§14.2의 `stepCountry`): 합계 계산 → 인력 → 자원 배분 → 생산 → 건설 → 연구 → 군(장비 손실, 모집, 최대 병력, 전투 보너스) → AI(10일마다) → 화면 데이터 표시.
- **준비 1분**(0~599틱): 달력이 1936-01-01에 멈춰 있고 날이 바뀌지 않으므로 경제는 돌지 않는다. 명령(건설 대기열, 라인, 연구, 법, 무역)은 받아서 상태에 넣는다. 600틱에 0일째 처리가 시작된다 *(내 판단: "준비 중 생산"은 설정만 된다는 뜻으로 읽는다)*.
- 0일째 처리는 600틱부터 606틱 사이에 나라별로 일어난다. 그 전의 화면 값(최대 병력 등)은 시작 상태(§11)가 계산해 둔 값이다.

## 3. 주 자료 확장 (`scenario.json` 버전 2)

### 3.1 새 필드

`ScenarioRegionSchema`에 다음을 더하고 `version`을 `2`로 올린다(버전 1 파일은 더 이상 읽지 않는다. 저장소의 두 파일 — 실제 지도와 테스트 지도 — 을 같이 다시 만든다).

| 필드 | 타입 | 뜻 |
|---|---|---|
| `cat` | `"wasteland" \| "pastoral" \| "rural" \| "town" \| "large_town" \| "city" \| "large_city" \| "metropolis" \| "megalopolis"` | 주 범주. 건물 칸 수를 정한다(§4.2) |
| `pop` | 정수 ≥ 0 | 1936년 인구, 천 명 단위 |
| `infra` | 정수 1~5 | 시작 인프라 |
| `core` | 불리언 | 1936 주인의 코어(본국)인가. 식민지·보호령·위임 통치령은 거짓 |
| `coastal` | 불리언 | 주 땅 타일 중 하나라도 해역 타일과 4방향으로 맞닿는가 |
| `civ`, `mil`, `dock` | 정수 ≥ 0 | 시작 민간 공장, 군수 공장, 조선소 |
| `res` | 정수 6개 튜플 `[석유, 알루미늄, 고무, 텅스텐, 강철, 크롬]` | 인프라 5일 때의 하루 산출(HOI4 단위) |

### 3.2 원본 표 (지도 생성 도구의 입력, 저장소에 넣는다)

- `map-generator/scenarios/world1936/src/economy1936.json`: 나라 79개마다 `{tag, popCore, popColonial, dev, civ?, mil?, dock?, infra?, nonCore?}`.
  - `popCore`, `popColonial`: 1936년 본국·식민지 인구(천 명). 역사 통계의 반올림 값(§11.1, §11.3).
  - `dev`: 산업화 정도 1~5. 공장·인프라를 공식으로 정하는 나라(메이저 아닌 나라)에 쓴다(§11.3).
  - `civ`, `mil`, `dock`, `infra`: 직접 정한 값(메이저 7개국과 몇몇 나라). 있으면 공식 대신 쓴다.
  - `nonCore`: 이 나라 땅 중 코어가 아닌 현대 나라 코드(`adm0_a3`) 목록. 도구의 `owners1936.json` `lowDetail`(식민지로 그리는 현대 나라)은 자동으로 비코어다. 예: 일본 `["KOR", "PRK", "TWN"]`, 미국 `["PHL", "PRI"]`.
- `map-generator/scenarios/world1936/src/resources1936.json`: 자원 산지 `{tag, res, amount, lon, lat, note}` 목록(§3.5). `tag`는 검증용이다(산지가 떨어진 주의 주인이 다르면 도구가 실패한다).

### 3.3 도구가 계산하는 방식 (결정적, 동점은 작은 주 번호)

1. **코어:** 주의 대표 1급 행정구역(`mainAdm`)의 `adm0_a3`가 `lowDetail`에도, 주인의 `nonCore`에도 없으면 코어.
2. **해안:** 주 땅 타일이 해역 번호 타일과 4방향으로 맞닿으면 참.
3. **도시 무게:** 주 안의 승점 도시 등급 합 `T`(`vp_cities.json`의 3·5·10·20)와 수도 여부.
4. **인구:** 나라의 `popCore`를 코어 주들에, `popColonial`을 비코어 주들에 무게 `w = (주 안 Natural Earth 인구 지점의 pop_max 합, 지점마다 최대 300만) + isqrt(tiles) × 2000`(수도 보너스 없음; 통제자 판정 2026-10-20)으로 나눈다(최대 나머지 방식). 비코어 주가 없는데 `popColonial > 0`이면 코어에 더한다.
5. **범주:** 아래 표에서 처음 맞는 줄 *(내 판단: HOI4 범주 이름을 쓰고 문턱은 인구·도시로 새로 정했다)*.

| 범주 | 조건 | 건물 칸 |
|---|---|---|
| megalopolis | 20등급 도시 && 인구 ≥ 8,000 | 12 |
| metropolis | 20등급 도시 \|\| 인구 ≥ 6,000 | 10 |
| large_city | 10등급 도시 \|\| 인구 ≥ 4,000 | 8 |
| city | 5등급 도시 \|\| 수도 \|\| 인구 ≥ 2,500 | 6 |
| large_town | 인구 ≥ 1,500 | 5 |
| town | 인구 ≥ 700 | 4 |
| rural | 인구 ≥ 200 | 2 |
| pastoral | 인구 ≥ 30 | 1 |
| wasteland | 그 밖 | 0 |

6. **인프라:** 코어 주 = `clamp(기준 + (T ≥ 10 ? 1 : 0) − (tiles > 6000 ? 1 : 0), 1, 5)`, 비코어 주 = `clamp(기준 − 2, 1, 5)`, wasteland는 1. 기준은 표의 `infra`, 없으면 `dev`.
7. **공장:** 나라의 조선소 → 민간 → 군수 순서로 하나씩 놓는다(동트 방식): 남은 칸이 있는 주 중 `w2 × 1000 ÷ (그 주에 이미 놓은 공장 + 1)`이 가장 큰 주에. `w2 = pop`(공장이 인구를 따른다; 비코어 주는 무게를 반으로, 그리고 코어 주에 칸이 없을 때만 — 통제자 판정 2026-10-20). 조선소는 해안 주에만. 칸이 모자라면 무게가 가장 큰 주의 범주를 한 단계 올리고 다시 놓는다(도구가 올린 주 수를 보고한다).
8. **자원:** 산지마다 경위도를 투영해 가장 가까운 땅 타일의 주에 더한다(기존 `nearestLand`, 반경 8픽셀). 같은 주의 같은 자원은 합한다.
9. **1936 보정 (통제자 판정 2026-10-20):** 미국 본국 인구는 1급 행정구역(州)별 1930년 인구조사(`economy1936.json` `admPop`)대로 나누고, 한 행정구역 안에서는 4의 무게로 주들에 나눈다. `src/industry1936.json`의 1936년 공업 지점이 그 주의 공장 무게 `w2`와 범주를 정하는 인구에 배수(기본 1)를 곱하고, 조선소는 같은 표의 1936년 해군 조선소 주에 그 무게의 동트 방식으로 먼저 놓는다(칸이 없으면 7의 규칙).

### 3.4 화면과 엔진이 읽는 곳

`ScenarioIndex`(engine-lib)가 v2 필드를 그대로 내준다. 새로 계산해서 내주는 것 *(로드할 때 한 번, 지도 타일 한 바퀴)*:

## 4. 건물과 건설

### 4.1 건물

| 건물 | 칸 | 비용(건설력) | P1에서 |
|---|---|---|---|
| 민간 공장 `civ` | 공유 칸 | 10,800 | 건설·소비재·무역에 쓴다 |
| 군수 공장 `mil` | 공유 칸 | 7,200 | 생산 라인에 넣는다 |
| 조선소 `dock` | 공유 칸 | 6,400 | **짓지 못한다.** 시작 조선소를 세고 화면에 보일 뿐이다(P4에서 짓고 쓴다) |
| 인프라 `infra` | 주 고유, 1~5 | 4,500 (한 단계) | 건설 속도와 자원 채굴을 올린다 |

비용은 HOI4의 감각을 따르되 인프라만 *(내 판단)*. 하루가 0.75초이므로 민간 공장 하나에 공장 15개를 넣으면 144일(108초)이다. 모드 설계서 §3.3의 목표(120~150일)와 맞는다.

### 4.2 건물 칸

- 주의 칸 = `floor(범주 칸 × (100 + 칸 보너스%) / 100)`. 칸 보너스는 산업 기술 `construction_1~3`이 하나에 +20%씩.
- 쓴 칸 = 그 주의 민간 + 군수 + 조선소 + **대기열에 있는 그 주의 공장 건설 남은 수**(대기열이 칸을 미리 잡는다).
- 인프라는 칸을 쓰지 않고 5가 최대다(대기열 포함).

### 4.3 건설 대기열

- 나라마다 대기열 하나, 최대 30개 항목. 항목 = `{주, 건물, 남은 수 1~10, 진행(밀리 건설력)}`.
- 쓸 수 있는 민간 공장(밀리): `freeCivMilli = max(0, 민간 × 1000 − 소비재 − 무역으로 낸 공장 × 1000 + 무역으로 받은 공장 × 1000)`. 소비재 = `(민간 + 군수) × 경제법% × 10`(밀리, 소수점은 HOI4처럼 공장 일부로 남는다).
- 대기열 앞에서부터 항목마다 `min(15000, 남은 freeCivMilli)`를 넣는다. 하루 진행 = `floor(넣은 밀리 × 5 × (100 + 속도%) / 100)`.
- 속도% = 인프라 `10 × (그 주 인프라 − 1)` + 기술 `construction_n` 하나에 10 + 무역법(자유무역 +10, 수출 중심 +5) + 경제법(군수 공장만: 민간 경제 −30, 초기 동원 −10, 부분 동원 +10, 전시 경제 +20, 총동원 +30) + 징병법 벌칙(확장 −5, 의무 −10, 전원 −20, 마지막 동원 −30) *(인프라·기술·법 수치는 내 판단, HOI4의 방향만 따름)*.
- 진행이 비용에 닿으면 건물 하나가 생기고(주의 숫자 +1), 남은 진행은 같은 항목의 다음 하나로 넘어간다. 항목이 끝나면 남은 진행은 버린다(HOI4와 같다).
- 완성하는 순간 칸이 모자라면(칸 보너스가 사라질 일은 없지만 주를 잃었다 되찾는 등) 그 항목을 지운다.
- 명령: 짓기(주, 건물, 수), 취소(항목 번호), 옮기기(항목 번호 → 새 자리). 짓기 조건: 내가 통제하는 주, 공장이면 **점령지가 아님**(§4.6), 조선소 아님, 칸·인프라 상한.

### 4.4 주 통제와 소유

- 주의 **통제국** = 그 주 승점 타일의 주인(P0 승점 통제와 같은 규칙). 승점 타일 주인이 없으면 통제국 없음.
- **점령지:** 통제국 ≠ 1936 주인이고 1936 주인이 살아 있고 항복하지 않았다. 공장과 자원은 50%(주마다 내림)만, 인력은 0.
- **합병지:** 통제국 ≠ 1936 주인이고 1936 주인이 항복했거나 죽었다. 공장·자원 100%, 인력은 비코어(10%).
- **본래 땅:** 통제국 = 1936 주인. 코어면 인력 100%, 비코어(식민지)면 10%.
- 코어·점령의 제대로 된 규칙(준수도, 저항)은 P5다.

### 4.5 통제가 바뀔 때 (하루 공통 처리)

- 그 주에 걸린 **다른 나라의 대기열 항목**을 지운다(새 통제국의 대기열은 건드리지 않는다).
- 공장은 주에 남는다(새 통제국이 쓴다, §4.4의 비율로). P4 전략 폭격·P5 초토화 전까지 공장은 부서지지 않는다.
- 화면에 바뀐 주를 보낸다(§14.4).

### 4.6 원작 건물과의 관계 *(내 판단)*

- 이 모드에서 원작 **도시**와 **공장**(기차)은 `disabledUnits`에 더해 짓지 못한다. 도시가 최대 병력을 올리던 규칙은 §6의 다리가 대신하고, 원작 공장은 이름이 겹쳐 헷갈린다.
- 항구, 방어 기지, 군함, 수송선, 무역선은 그대로 둔다(P2·P4가 대체할 때까지 원작 전쟁의 도구). 원작 금도 그대로 쌓이고 이 건물들에 쓴다.

## 6. 인력과 병력 다리 (P2가 사단으로 대체할 때까지)

### 6.1 단위

- **원작 병력 1 = 병사 1명.** 원작 화면은 병력을 10으로 나눠 보인다(`renderTroops`). 이 모드의 화면도 병력·인력을 같은 함수로 보여 숫자가 서로 맞는다(독일 48만 명 = "48K"). 보병 장비 1개 = 병사 10명 = 화면의 병력 1 *(내 판단: 원작 공격 공식의 절대 상수를 건드리지 않으려고 내부 단위를 원작과 같게 둔다)*.

### 6.2 모집 가능 인구와 인력

- `recruitable = Σ(통제하는 주) pop × 1000 × 인력 비율 × 징병법 천분율 / 1000 × (100 + 교리%) / 100`. 인력 비율은 §4.4(코어 100%, 비코어·합병 10%, 점령 0%) *(비코어 10%는 내 판단: HOI4는 2%지만 1936 식민지 징집을 조금 남김)*.
- **인력 풀** `manpower`(명): 시작 값 `max(0, recruitable − 시작 병력)`.
- 하루: `manpower = min(manpower + floor(recruitable / 3650), max(0, recruitable − 병력))`. 해마다 모집 가능 인구의 10%가 새로 자란다 *(내 판단)*.
- 징병법을 올리면 그날 `manpower += 새 recruitable − 옛 recruitable`, 내리면 그만큼 빼되 0 아래로 안 간다. 주를 얻고 잃는 것은 위의 상한으로만 반영된다.

### 6.3 모집 (원작 병력이 느는 유일한 길)

- 이 모드에서 `Config.troopIncreaseRate`는 0이다. 원작의 틱마다 회복이 없다.
- 하루에 나라마다: `r = min(manpower, 보병 장비 비축 × 10, trainCap)`, `trainCap = max(500, floor(recruitable / 90) × (100 + 교리%) / 100)`(HOI4 훈련 90일의 감각). `r`명을 병력에 더하고, 인력 `r`과 보병 장비 `ceil(r / 10)`개를 쓴다(새 세대부터).
- 보병 장비는 "전선에 나간 것"을 따로 센다: `fieldInfUnits`(개수), `fieldInfGenSum`(세대 합). 평균 세대가 전투 보너스(§10)를 정한다.

### 6.4 최대 병력

- 이 모드에서 `Config.maxTroops(p) = max(p.troops(), wwTroopCap)`, `wwTroopCap = 병력 + min(manpower, 보병 장비 비축 × 10)`(하루마다 계산해 상태에 둔다). 원작 도시 보너스·면적 공식은 쓰지 않는다.
- 여기서 `병력`은 **군 전체**(`WwEconomy.armyMen`: 집 병력 + 나간 공격 + 수송선)다. 집 병력만 세면 공격을 보낸 다음 날 AI가 다시 "가득 찼다"고 보고 피를 다 흘릴 때까지 공격을 거듭 보낸다 *(밸런스 판정, P1 Task 3 고침)*.
- 화면의 원작 병력 막대(최대 병력)는 그대로 이 값을 보인다. AI의 원작 공격 판단(병력/최대 병력)도 이 값을 본다.

### 6.5 잃은 병력

- 원작 공격에서 병력이 줄면(공격 쪽 손실, 방어 쪽 손실 모두) `AttackExecution`이 경제에 그 수를 알린다(`noteCombatLoss`). 그날 나라 처리에서:
  - 전선 보병 장비: `fieldInfUnits`를 잃은 비율만큼 줄인다(세대 합도 같은 비율).
  - 나머지 지상 장비(지원, 포, 대전차, 대공, 트럭, 전차): 비축의 `잃은 비율 × 50%`를 잃는다 *(내 판단)*.
  - 잃은 사람은 돌아오지 않는다(인력으로 돌아가지 않음).
- 이 모드에서 원작 공격의 양쪽 손실에 `WW_LOSS_SCALE_PCT = 60%`를 곱한다(§10). 원작은 1분 만에 병력을 다시 채우지만 이제는 장비 생산 속도로만 채우므로, 손실도 같이 줄인다 *(내 판단, P2가 대체)*.
- 원작 병력 증여(같은 진영, P0 고침으로 켬)는 사람과 장비를 따로 옮기지 않는다: 받은 나라 병력만 는다.

### 6.6 P0 시작 병력의 변경

P0의 "시작 병력 = 최대 병력의 50%"(`WW_START_TROOPS_PCT`)는 P1의 시작 군대(§11)로 바뀐다. P0 모드 고정값(VanillaDigest의 ww 변형)은 다시 잡는다.

## 7. 자원과 무역

### 7.1 산출

- 나라의 자원 산출 = `Σ(통제하는 주) floor(res × (75 + 5 × 인프라) / 100 × 통제 비율 × (100 + 채굴%) / 100)`. 인프라 5에서 100%, 1에서 80% *(내 판단)*. 통제 비율은 점령지 50%, 그 밖 100%. 채굴%는 기술 `excavation_1~2`(각 +10%).

### 7.2 쓰는 곳

- 생산 라인마다 **공장 하나당** 장비가 정한 자원이 든다(§8.2 표). 라인이 받은 자원이 모자라면 산출이 준다.

### 7.3 배분 (HOI4처럼 라인 순서대로)

- 쓸 수 있는 양 = 산출 − 수출 + 수입(자원마다).
- 라인을 화면 순서(위가 먼저)대로 돌며 자원마다 `min(필요, 남은 양)`을 준다. 라인의 **충족률**(천분율) = 자원별 받은 양 / 필요의 최솟값(필요 없는 라인은 1000).
- 라인 산출 배율 = `200 + 800 × 충족률 / 1000`(천분율). 자원이 전혀 없어도 20%는 나온다 *(내 판단: HOI4의 부족 벌칙을 정수 하나로)*.
- 부족한 자원은 위쪽 띠의 경고 점과 산업 서랍 "자원" 탭에서 빨갛게 보인다.

### 7.4 무역 거래

- 거래 = `{번호, 사는 나라, 파는 나라, 자원, 민간 공장 수 k}`. 사는 나라는 하루 `8k`단위를 받고, 민간 공장 `k`개를 낸다(건설에 못 씀). 파는 나라는 `k`개를 받는다(건설에만 씀). HOI4와 같다.
- **상대가 될 수 있는 나라**(사는 쪽 기준) *(내 판단: 모드 설계서 §6.2 "P1은 이웃·같은 진영"을 다음으로 정함)*:
  1. 같은 진영, 또는
  2. **육로 이웃:** 지금 주 통제로 만든 나라 이웃 그래프에서, 사는 나라와 전쟁 중이 아닌 나라만 거쳐 닿는다(철도 무역. 독일 → 체코 → 헝가리 → 루마니아), 또는
  3. **바다 이웃:** 두 나라 모두 같은 해역에 닿는 해안 주를 통제한다(발트해의 독일과 스웨덴, 영불 해협). 먼 바다 무역은 수송선단과 함께 P4.
- 그리고: 전쟁 중이 아님, 둘 다 살아 있고 항복하지 않음, 파는 쪽이 사는 쪽에 통상 금지를 걸지 않음, 자기 자신 아님.
- 파는 나라의 남은 수출 여유 = `floor(산출 × 무역법 수출% / 100) − 이미 판 양` ≥ `8k`.
- 명령: 거래 열기(파는 나라, 자원, k), 거래 닫기(번호). 한 나라가 열 수 있는 거래는 최대 20개.

### 7.5 매일 검사 (하루 공통 처리, 번호 순)

- 상대 조건이 깨진 거래(전쟁, 통상 금지, 길이 끊김, 항복)는 닫는다.
- 파는 나라의 수출 여유가 모자라면 그 나라의 거래를 **새것부터** 닫는다.
- 사는 나라가 낸 공장이 `민간 − 소비재`를 넘으면 사는 나라의 거래를 새것부터 닫는다.
- 닫힌 거래는 사는 나라에게 알림(`ww1936_trade_closed {sellerTag, resource}`).

### 7.6 AI의 수락

파는 쪽은 사람이든 AI든 자동으로 판다(조건만 맞으면). AI 사이의 거래는 §12.

### 8.2 라인

- 라인 = `{번호, 장비, 세대, 공장 수, 효율(bp), 진행(밀리 산업력), 충족률}`. 나라마다 최대 20개, 순서가 자원 우선순위다.
- **공장 배정:** 쓸 수 있는 군수 공장(점령지는 50%) 합보다 배정이 많으면 **아래 라인부터** 공장을 뺀다. 남는 공장은 놀고 화면에 "놀고 있는 공장 N"이 보인다.
- **하루 산출** = `공장 × 4500 × 효율 / 10000 × (100 + 산출%) / 100 × 자원 배율 / 1000`(밀리 산업력). 산출% = 기술 `output_1~2`(각 +10) + 경제법 + 징병법 벌칙. 진행이 장비 하나의 비용(밀리)에 닿을 때마다 비축 +1, 진행에서 뺀다.

### 8.3 효율 (HOI4 공식)

- 기준점(bp, 10000 = 100%). 바닥 `1000`(10%), 기본 상한 `5000`(50%), 기술 `tools_1~4`가 하나에 +1000(최대 9000).
- **하루 증가** = `max(1, floor(상한² / (1000 × 효율)))` bp, 상한을 넘지 않는다. HOI4의 하루 `0.001 × 상한² ÷ 효율`(분수)과 같다. 10%에서 시작한 라인은 상한 50%에 약 480일(6분)에 닿는다.
- **공장 더하기:** 새 공장은 바닥 효율로 들어와 평균을 낮춘다: `효율 = floor((효율 × 기존 + 1000 × 더한 수) / (기존 + 더한 수))`. 빼기는 효율을 바꾸지 않는다.
- **장비 바꾸기:** 같은 장비의 다른 세대는 효율의 80%, 같은 계열(보병 = 보병·지원, 포 = 포·대전차·대공, 차량 = 트럭·경전차·중형, 항공 = 전투기·폭격기)은 50%, 다른 계열은 30%를 남긴다(바닥 아래로는 안 감). 기술 `flexible_line`이 남기는 비율에 +10%p *(남기는 비율은 내 판단, HOI4의 "전환 손실"을 셋으로 단순화)*. 진행은 0으로 돌아간다.
- **상한이 내려가지는 않는다**(기술은 잃지 않는다).

### 8.4 명령

- 라인 더하기(장비, 세대, 공장 수), 라인 바꾸기(번호, 장비, 세대), 공장 수 정하기(번호, 수), 라인 지우기(번호), 라인 옮기기(번호 → 자리).
- 세대는 그 세대의 기술이 있어야 한다.

## 9. 연구

### 9.1 칸

- 기본: 메이저 3, 그 밖 2. 공장(민간 + 군수) 50개 이상 +1, 100개 이상 +1, 최대 5 *(내 판단: 칸 +2는 P3 중점의 몫이었지만 P1에서 3~5를 쓰려고 공업력에 묶음. P3 중점은 이 위에 더한다)*.
- 칸 수가 줄면 뒤쪽 칸의 연구는 멈춘다(진행은 남는다).

### 9.2 속도

- 기술의 기본 날수 = `120 + 15 × (연도 − 1936)`(1936년 120일 = 90초, 1942년 210일).
- 하루 진행(밀리일) = `floor(1000 × (100 + 연구 속도%) / (100 + 앞섬%))`. 연구 속도% = 전자 기술(+3, +5, +5) + 자유무역 +5. **앞섬%** = `max(0, floor((그 연도 1월 1일 − 오늘) × 100 / 365))` — 연도보다 1년 이르면 2배 걸린다. 날마다 다시 계산하므로 시간이 지나면 벌칙이 준다(HOI4와 같다).
- 진행이 `날수 × 1000`에 닿으면 끝난다. 남은 진행은 버린다.

### 9.3 규칙

- 선행 기술이 있어야 시작한다. 같은 기술을 두 칸에서 할 수 없다.
- **교리:** 지상 교리 네 학파(기동전, 화력 우세, 전투 계획, 인해 전술) 중 **하나만** 연다. 한 학파의 1단계를 시작하면 다른 학파 1단계는 막힌다(HOI4의 한 갈래 선택).
- 연구를 취소하면 진행을 버린다. 끝나면 주인에게만 알림(`ww1936_research_done {tech}`).

## 10. 전투 다리 (P2가 대체)

### 10.1 나라의 전투 수치 (하루마다 계산해 상태에 둔다)

- 장비마다 **충족률** = `min(1000, 비축 × 1000 × 100000 / (병력 × 기준))`(천분율, 병력 0이면 0). 기준은 §8.1 표.
- 보너스 = `Σ 충족률 × 표 보너스 × 세대 배율 / 1000`, 세대 배율 = 그 장비 비축의 평균 세대로 100/130/160 사이를 정수 보간. 보병은 전선 장비 평균 세대로 `(평균 − 1) × 10`(공격·방어).
- 교리 효과를 더하거나 곱한다(§9.4). 결과는 정수 `attackPct`, `defensePct`, `speedPct`. 각각 0~200으로 자른다.

### 10.2 원작 공격에 적용 (`AttackExecution`, 이 모드에서만)

- 공격 쪽 손실 배율 × `(100 + 상대 defensePct) / (100 + 내 attackPct) × 60 / 100`
- 방어 쪽 손실 배율 × `(100 + 상대 attackPct) / (100 + 내 defensePct) × 60 / 100`
- 공격 속도 배율 × `(100 + 내 speedPct) / 100`
- 땅 주인이 없는 타일은 이 모드에 없다. 계산은 engine-lib 순수 함수(`wwCombatScales`)로, 화면이 같은 값을 보일 수 있다.

예(어림값): 1939년 독일(공격 50, 방어 25, 속도 20) 대 폴란드(포 충족 30%, 지원 20%: 공격 5, 방어 4). 독일 손실 × 0.60 × 104/150 = 0.42, 폴란드 손실 × 0.60 × 150/104 = 0.87, 속도 × 1.2.

### 11.3 메이저가 아닌 72개국 (공식)

- 법: 민간 경제, 수출 중심, 제한 징병. 영연방(캐나다, 오스트레일리아, 뉴질랜드, 남아프리카, 영국령 인도)과 아일랜드는 지원병.
- 시작 군대 = `max(1000, floor(recruitable × 30 / 100))` (폴란드 약 25만, 벨기에 약 6만, 중국 국민정부 약 225만 — 1936년 국민혁명군 170만~200만과 비슷하지만 장비가 모자라 최대 병력이 금방 막힌다).
- 시작 기술: `inf_eq_1`, `support_eq_1`, `artillery_1`; `dev ≥ 3`이면 `motorized_1`, `fighter_1`도.
- 시작 비축: 보병 장비 예비 = 시작 군대의 1%(10명당 1개의 10%), 포 = 충족 30%, 지원 = 20%, `dev ≥ 3`이면 전투기 `(civ + mil) × 10`.
- 72개국의 `popCore`, `popColonial`, `dev`는 계획 Task 2의 표(1936년 인구의 반올림, 산업화 정도는 내 판단). 예: 폴란드 34/0/3, 체코슬로바키아 15/0/4, 벨기에 8.3/10(콩고)/5, 네덜란드 8.5/61(동인도)/5, 스웨덴 6.3/0/5, 중국 국민정부 300/0/1, 만주국 34/0/2, 영국령 인도 350/0/1, 브라질 38/0/2, 캐나다 11/0/4.

## 12. AI 경제

AI 나라마다 10일에 한 번(`(날 + smallID) % 10 === 0`) 다음을 차례로 한다. 사람과 같은 명령 함수를 직접 부른다(인텐트를 만들지 않는다). 무작위는 쓰지 않는다.

*(Task 9 밸런스, §16 기록)* 0일째는 메이저 7개국의 첫 차례이기도 하다. 차례와 차례 사이에는 무엇이 비면 그날 바로 그 단계만 다시 한다: 빈 연구 칸(연구), 노는 군수 공장(라인), 대기열이 다 받지 못하는 민간 공장(건설). 법과 무역, 세대 올리기는 차례에만 한다.

### 12.1 성향 *(내 판단)*

| 성향 | 나라 | 군수 전환 날짜 | 경제법 목표 |
|---|---|---|---|
| 침략국 | 독일, 이탈리아, 일본, 소련 | 1936-07-01 *(Task 9, 처음 1937-07-01)* | 부분 동원(시작), 전시 경제(전쟁 중), 총동원(전쟁 1년) |
| 민주국 | 영국, 프랑스, 미국과 영연방 | 1939-01-01 | 초기 동원(1938), 부분 동원(1939 또는 전쟁), 전시 경제(전쟁 180일) |
| 소국 | 그 밖 | 1938-01-01 | 초기 동원(1938), 부분 동원(전쟁), 전시 경제(전쟁 1년) |

### 12.2 순서

1. **법:** 경제법을 성향 목표로(조건이 되면). 징병법: 전쟁 중이면 확장 → 의무(인력 < 모집 가능의 20%일 때) → 그다음 단계(조건이 되고 인력이 바닥일 때). 평시에는 1938년 이후 침략국만 확장. 무역법은 바꾸지 않는다.
2. **건설:** 대기열 항목 수를 `ceil(freeCiv / 15) + 1`개까지 채운다. 전환 날짜 전에는 민간 공장, 뒤에는 군수 공장 3 : 민간 1(전쟁 중이면 군수만). 전환 뒤에는 대기열의 군수 공장을 앞으로, 그다음 인프라, 민간 공장을 뒤로 옮긴다(진행은 남는다, Task 9). 주 고르기: 남은 칸이 있는 통제 주 중 인프라 높은 순, 같으면 칸이 많은 순, 같으면 번호 순. 칸이 없으면 자원이 있는 주의 인프라.
3. **라인:** 목표 비율(메이저: 보병 40%, 지원 5%, 포 15%, 대전차 5%, 대공 5%, 트럭 5%, 전차 15%(중형이 있으면 중형), 전투기 5%, 폭격기 5%; 소국: 보병 60%, 포 20%, 지원 10%, 대전차 10%). 놀고 있는 공장을 목표와 차이가 가장 큰 장비 라인에 넣는다(없으면 라인을 만든다). 중형 전차를 연구한 뒤에는 경전차 라인의 공장도 전차 몫에 센다(Task 9). 새 세대가 있고 라인 효율이 상한 − 5%p 이상이면 세대를 올린다(한 차례에 하나, 거절되면 다음 라인). 보병 장비 비축이 인력 / 10보다 많으면 보병 몫을 5%p 줄인다(장비가 남아돈다).
4. **연구:** 빈 칸마다 우선순위 목록(침략국: 도구 → 보병 → 포 → 기갑 → 건설 → 교리(독일 기동, 소련 인해, 이탈리아 화력, 일본 인해); 민주국: 건설 → 도구 → 보병 → 포 → 전자 → 교리(영국·미국 화력, 프랑스 전투 계획); 소국: 건설 → 보병 → 포 → 교리(전투 계획))에서 앞섬이 180일 이하인 첫 기술. 그런 기술이 없으면 앞섬 9개월(75%) 이하인 첫 기술(Task 9, 처음 1년).
5. **무역:** 라인 충족률이 1000 미만인 자원마다 모자라는 양을 `ceil(부족 / 8)`개 공장만큼 산다(한 번에 자유 민간 공장의 30%까지, 30%가 0으로 내려가도 자유 민간 공장이 하나 있으면 하나 — Task 9). 상대: 수출 여유가 가장 큰 나라(같은 진영 먼저, 동점은 smallID). 수입이 필요보다 8 이상 남으면 가장 새 거래부터 닫는다.

## 14. 결정성·상태·업데이트·성능

### 14.1 상태

- 모두 `WorldWar.economy: WwEconomy` 안에 있다. 나라 상태는 smallID로 색인한 배열, 주 건물은 주 번호로 색인한 `Uint8Array` 4개(민간, 군수, 조선소, 인프라).
- 하루 처리 결과(합계, 최대 병력, 전투 수치, 자원 배분, 자유 민간 공장)도 **상태로 저장한다**: 다음 하루 처리 전에 다른 코드(`Config.maxTroops`, `AttackExecution`)가 읽기 때문이다. 복원할 때 다시 계산하지 않는다(P0 규칙: 복원은 대입만).
- 숫자는 모두 정수: 인구·사람·장비·자원은 정수, 건설·생산 진행은 밀리, 효율은 bp, 충족률은 천분율. `Math.floor`·`Math.min`·`Math.max`와 정수 곱·나눗셈만 쓴다. 곱이 2^53을 넘지 않게 순서를 정한다(인구 × 천분율 ≤ 5×10^11).
- PRNG를 쓰지 않는다.

### 14.2 실행

- 시계 `WorldWarExecution.tick`이 P0 처리 뒤에 `economy.tick(ticks)`를 부른다(하루 공통 처리 + 그 틱의 나라 몫).
- 명령은 인텐트 하나 `ww_order {order}`(목록 맨 뒤)로 받고, 실행 `WwOrderExecution`이 `order.kind`로 각 갈래 함수에 넘긴다. 서버 `IntentAuthorization`은 다른 인텐트처럼 보낸 사람 자기 나라에만 적용된다(인텐트에 대상 나라가 없다).
- AI는 하루 처리 안에서 같은 함수를 부른다.

### 14.3 스냅샷·해시

- `WorldWarStateSchema`에 `economy: WwEconomyStateSchema.optional()`. 모드가 켜진 게임은 항상 쓴다. P0 시절 스냅샷(경제 없음)은 복원을 거절한다(P0 판을 P1 코드로 이어 갈 길은 없다).
- `WorldWar.hash()`에 `economy.hash()`(나라별 병력 상한, 인력, 비축 합, 공장 수, 연구 완료 수, 주 건물 합)를 더한다.
- 화면 갱신 표시(`dirtyCountries`, `dirtyRegions`)는 `DERIVED_FIELDS`.

### 14.4 화면 업데이트

`GameUpdateType.WwEconomy`(맨 뒤), 틱마다 그 틱에 처리한 나라와 바뀐 주만:

```
WwEconomyData {
  countries: WwCountrySummary[]   // 그 틱에 처리한 살아 있는 나라 전부
  details:   WwCountryDetail[]    // 그중 사람 나라만(대기열, 라인, 연구, 거래, 법, 비축, 자원 표)
  regions:   WwRegionData[]       // 통제나 건물이 바뀐 주
}
```

- 요약(나라마다 약 12개 숫자)은 모든 나라의 최대 병력(`PlayerView.wwTroopCap`), 순위표의 공장 수, 무역 상대 목록에 쓴다.
- 자세한 정보는 사람 나라만 보낸다(관전자는 사람 나라만 자세히 본다) *(내 판단: 79개국 전부 보내면 하루 약 100KB)*.
- 화면 `GameView`가 `WwEconomyView`를 들고 업데이트를 합친다. 주 건물의 첫 값은 화면이 `scenario.json`에서 스스로 만든다. 나라 값은 엔진이 시작할 때 모든 나라를 "바뀜"으로 표시해 첫 틱의 업데이트에 다 담기고, 그 전 한 틱 동안 `PlayerView.wwTroopCap()`은 지금 병력을 돌려준다.

### 14.5 옵션이 꺼졌을 때

`WwEconomy`는 `WorldWar`가 있을 때만 생긴다. 모든 연결(`Config.maxTroops`, `troopIncreaseRate`, `AttackExecution`, `PlayerImpl.wwTroopCap`)은 `wwTroopCap() === null`이나 `worldWar() === null`이면 지금 코드 그대로다. `VanillaDigest`의 모든 고정값이 그대로 통과한다. **모드가 켜진 고정값과 P0의 ww 스냅샷 오라클은 바뀐다**(시작 병력, 원작 회복 없음). P1 Task 1이 새 값으로 다시 잡는다.

### 14.6 성능

- 하루 공통 처리: 주 1,265개의 승점 타일 주인 읽기, 거래 수십 개 검사, 나라 이웃 그래프(주 이웃 쌍 약 3,500개)와 나라 79개의 너비 우선 탐색. 하루 한 번.
- 나라 처리: 통제 주 합산(나라 목록을 날마다 다시 만들지 않고 하루 공통 처리에서 나라별 주 목록을 만든다), 라인 ≤ 20, 대기열 ≤ 30, 칸 ≤ 5.
- `ScenarioIndex`의 주 이웃·해역 이웃은 처음 쓸 때 지도 타일을 한 번 돈다(814만 타일, 데스크톱 약 30ms).

## 18. P2로 넘기는 것

- P2의 사단은 비축 장비를 편제대로 가져간다. P1의 `fieldInfUnits`·전투 다리·`wwTroopCap`·`WW_LOSS_SCALE_PCT`·`noteCombatLoss`는 P2가 지운다. 인력 풀, 비축, 라인, 건설, 연구, 법, 무역은 그대로 쓴다.
- 요새 건물(주 고유 1~5)은 P2가 `BUILDING_IDS` 맨 뒤에 더한다. 조선소 건설은 P4.
