# 인계 문서 — Statecraft "World War 1936" 모드 (2026-11-01)

다른 컴퓨터·다른 계정의 Claude Code 세션이 이어서 작업하기 위한 문서다. 시작할 때 이 파일을 먼저 읽고, 필요할 때 같은 폴더의 설계 문서를 읽는다. 저장소 규칙은 루트의 `CLAUDE.md`에 있다.

## 1. 프로젝트 한 줄

## 2. 사용자(소유자)와 일하는 방식 — 꼭 지킬 것

- **모든 답은 한국어로.** 짧은 진행 보고도 한국어.
- **기능을 줄여서 빨리 하는 건 싫어한다.** 줄일 수 있는 건 테스트뿐이다.
- **토큰을 아낀다.** 보고는 짧게, 필요한 파일만 읽고, 감사·전수 점검을 묻지 않고 돌리지 않는다("하지마 뭔 테스트야"). 더 할 일을 찾으라고 하면 아이디어 목록만 내고 실행하지 않는다.
- 작업은 서브에이전트(가벼운 모델 우선)에게 맡기고, 본 세션은 조율·합치기·보고를 한다. 독립된 일은 병렬로.
- **"배포해" = 서버 배포 + GitHub 푸시(`atlas-home`과 `main`)까지 한 번에.** "푸시해"만 들으면 푸시만. 시키지 않으면 배포·푸시하지 않는다.
- **"정리"** 라고 하면 4부분 보고: 한 일 / 남은 시간 / 사용자가 정할 것 / 내가 정한 것(이유 한 줄씩).
- 질문은 최소로. 정할 게 있으면 추천안을 붙여 묻는다("추천대로"라고 답하는 경우가 많다).
- **역사는 양념이다.** AI는 상황 판단, 판마다 결과가 달라야 한다. 정확한 날짜 맞추기 금지.
- **옛 민감 규칙(한반도·대만 제한, 일본 인물 직함 표기, 식민 콘텐츠 금지, 깃발 제외)은 2026-10-31에 폐지됐다.** 실존 인물 실명·역사 그대로 쓴다. 단, 학살·강제노동 같은 잔학 행위를 게임 보너스로 만들거나 미화하지 않는다(`tests/ww1936/Sensitivity.test.ts`가 잔학 용어만 금지).
- HOI4 원문 문구를 그대로 쓰지 않는다(`tests/ww1936/Originality.test.ts`).

## 3. 엔진 규칙 (CLAUDE.md 요약 + 이 모드의 관례)

- 결정성: 정수 연산, 시드 굴림(`wwRoll`), Map/Set 순서 의존 금지. 새 상태는 스냅숏·복원·해시에 넣는다.
- 다이제스트: `tests/ww1936/WorldWarSnapshot.test.ts`의 `WW1936_DIGEST`/`WW1936_EASY_DIGEST`는 게임 흐름이 바뀌면 **세 번 같은 값 확인 후** 다시 고정하고 이유를 주석으로 단다. `VanillaDigest`는 절대 바뀌면 안 된다. 여러 갈래를 병렬로 할 때는 갈래에서 고정하지 말고 합친 뒤 한 번만 고정한다.
- 패키지 경계: 규칙은 engine-lib, 상태는 engine, 계약 타입은 engine-api. 클라이언트는 engine을 import하지 않는다(`tests/LayerBoundaries.test.ts`).
- 문구: `translateText`, `resources/lang/en.json`과 `ko.json`만. en.json은 키 정렬 유지(`tests/EnJsonSorted.test.ts`). 한국어는 `}` 뒤 한글 앞에 띄어쓰기.
- 덧붙이기 전용 목록(`WW_ORDER_BLOCKS`, 주문 종류, `WW_TECH_IDS` 등)은 지우지 말고 끝에만 붙인다(직렬화·해시 순서).
- 속도 측정 테스트(EconomyPerf, EndgamePerf, LandPerf, SeaAirPerf, NavyPerf)는 컴퓨터가 바쁠 때 떨어진다. 하나씩 다시 돌려 확인.
- `git add -A` 금지. 병렬 에이전트는 임시 스크립트를 갈래별 폴더에 둔다(공유 폴더 `gen.py` 덮어쓰기 사고가 있었다).
- 의존성 추가 금지(설치: `npm run inst`, Node 24, npm 12).

## 5. 다음 작업: 전쟁 시스템 개편 (결정 완료, 사용자가 "진행해" 하면 시작)

설계: `docs/handoff/ww6-war-design.md` (진단 도구는 브랜치 `w6-wardiag`: 전쟁 기록기 + `scripts/ww1936/war-diag.ts`). 설계안 중 **사용자가 바꾼 결정**이 우선이다:

1. **전선 방식 = "군 목표 명령"** (설계안의 선 긋기 FrontLine 대신):
   - 군 토큰 누름 → 행동 줄 **[공격] [방어] [이동] [자동]** + 공세 강도 스위치(신중/보통/과감, 기본 보통).
   - [공격]: 목표 지역 1~3곳 탭 → 지도에 화살표, 이 군의 담당 국경 칸이 **군 색으로 칠해지고**, 칸마다 승산 배지(낮음/보통/높음) → [실행].
   - [방어]: 군 주변 국경 구간을 맡음(칸을 탭해 늘리고 줄임).
   - 엔진: 담당 칸을 **먼저 한 사단씩 모두 채우고** 남는 사단은 공격 축에 몰아 줌, 지친 사단 교대, 목표 도달 시 방어로 전환, **군 사이 빈칸은 가까운 군이 메움**.
   - **아무도 안 맡은 국경 칸은 빨갛게 깜빡임.** 전투 칸에 전투 아이콘과 띠 진행 막대.
   - [자동] = "수비 자동"(국경만) / "공세 자동"(AI처럼). AI도 같은 명령 방식을 쓴다.
2. **점령 = 깊이 띠** (지역을 1~5띠, 띠마다 다시 싸움, 승점 도시는 마지막 띠).
3. **운 = 전술 + 주도권 + 하루 운 ±10%** (시드 굴림, 미리보기는 승산 범위).
4. **항복 = 추천안 + 프랑스 바닥 25%**: 수도를 쥐고 있으면 항복선 +15%p(최대 95), 게이지는 선 위에서 하루 `+1 + ⌊넘은 %p ÷ 5⌋`·선 아래 −2, 45에 항복, 완전히 넘어간 지역만 셈, 프랑스 하한 25%.
5. **배포는 한 번에** (엔진 먼저 내지 않음).
6. 방어 강화(참호 단계당 +5%·2일에 1단계, 남는 진지 0~3단계, 도시 피해 −15%), 성능 목표(사단 2,000에 지상전 틱 +10% 이내)는 설계안대로.

예상: 갈래 병렬로 약 30시간 분량, 실제 하루 안팎. 토큰이 많이 드니 가벼운 모델 우선, 갈래 수는 필요한 만큼만.

## 6. 배포 (원래 컴퓨터에서만)

친구 서버는 원래 컴퓨터의 `~/dev/OpenFrontIO`(브랜치 `atlas-home`)에서 `npm run selfhost:*` 스크립트로 돌고, Cloudflare 터널로 `front.eserlic.cloud`에 연결된다. **다른 컴퓨터에서는 GitHub 푸시까지만** 할 수 있다. 원래 컴퓨터에서 반영:

```bash
cd ~/dev/OpenFrontIO
npm run selfhost:stop
git pull            # atlas-home
npm run inst        # 의존성이 바뀌었을 때
npm run selfhost:start
```

푸시 절차(어느 컴퓨터든): 작업 브랜치를 `atlas-home`에 앞으로만 합치기(ff) → `git push origin atlas-home atlas-home:main`. 이 `handoff` 브랜치는 문서만 더한 것이니, 작업 결과를 `atlas-home`에 합칠 때 `docs/handoff/`는 빼도 된다.

두 번째 서버(레드햇 ARM, `front2.eserlic.cloud`, 터널 `statecraft2`)는 같은 명령으로 `git pull` 후 재시작하면 된다.
